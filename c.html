      How this works
      1. Look up the chemical on the Chemical tab — type a name, CAS number or PubChem CID. The name, formula, hazard statements and pictograms fill in automatically.
      2. Set the concentration, then press Apply concentration cut-offs on the Hazards tab. A dilute solution is often classified lower than the concentrated chemical, or not at all.
      3. Check everything against the supplier's SDS and edit anything that looks wrong — every field stays editable.
      4. Queue and print. Add labels to the print queue, or fill a whole page with one chemical, then preview the sheet before printing.

      Nothing here replaces the SDS. Treat every fetched label as a first draft.

      Labels to check

      Bromine water, limewater, Fehling's and the rest are mixtures, so PubChem has no record of them — a search either finds nothing or finds the pure chemical, whose classification is not theirs.

      Heading
      Kept for the record and for the QR code. The name printed on the label should be the one on the supplier's SDS, so a systematic name normally belongs here rather than in the Name field.
      Digits after a symbol drop automatically as subscripts; a trailing + or - rises as a charge. Use ^ or _ to force it (SO4^2-).
      Identifiers
      Carries the name, formula, CAS, signal word, hazard codes, DG class, where to store it and what to keep it away from. Only added when the label is at least 80 × 50 mm — smaller than that a code cannot be printed large enough to scan reliably, so it is left off rather than shrunk.

      Mixture — work the classification out from what went in

      For a solution of one chemical in another — “bromine solution 5% in carbon tetrachloride” — there is no compound record to look up, because the mixture is not a compound. Name what is in it and how much, and the classification is worked out from the components using the same cut-offs the Hazards step uses for a dilution.

      Supplier details (required on original containers)
      Put this same HTML file on a web address staff and students can reach, and paste that address here. The chemical's details travel inside the QR code itself, so nothing is uploaded and no database is needed — the page just reads them back. Without a reachable address no QR code can be printed, because there would be nothing for a scan to open.
      A QR code supplements the printed label, it never replaces it. The GHS elements — product name, signal word, hazard statements and pictograms — have to be readable on the container itself. Use the code for the detail that will not fit.
      Where to publish this file so scans work on every phone

      You publish one file — this one — and never touch it again as you add chemicals. Each chemical's details ride inside its own QR code, so the hosted page holds no chemical data and needs no updating.

      Free options that work:

      • Netlify Drop — drag the file onto app.netlify.com/drop. No account needed to start. Fastest way to test one code before committing to anything.
      • GitHub Pages — free and permanent, needs a GitHub account. Good if this will be in use for years.
      • Cloudflare Pages — same idea, drag-and-drop deploy.
      • Your own school or department web space — best of all if you can get it, because the domain is already trusted by the school's web filter.

      What will not work, and why:

      • Teams / SharePoint / OneDrive — two separate blockers. Viewers are sent to a login, and SharePoint serves .html files with a download header instead of rendering them, which is the default and can no longer be switched off in most tenants.
      • Google Drive and Dropbox — both withdrew HTML page hosting years ago; shared links download the file.
      • A file on this computer — a phone cannot reach it, and camera apps ignore file:// links.

      Before printing a batch, scan one test code on a school-managed device, not just your own phone. Web filtering may block an unfamiliar domain, and getting one address allowlisted is a much smaller ask than a server.

      Safety card files

      Each card is one self-contained HTML file — artwork and text baked in, no internet, nothing to install. Put them on a shared drive or a USB stick and they open on any computer, tablet or phone. They are not what a QR code can point at, though: a phone scanning a code has to reach the page over the web, and cannot open a file sitting on someone else's computer.

      Storage notes file

      One note per chemical, kept apart from the labels because the note describes the chemical and the prep room, not the bottle. Twenty decants of nitric acid share one note. Export it to keep a copy, or to give the same notes to another prep room.

      Border colours — segregation groups

      The border says which cabinet a bottle goes back in. Red, yellow and blue come straight from the dangerous goods diamonds for classes 3, 5.1 and 4.3 so they do not fight that convention. Class 8 is one diamond covering both acids and bases, so it splits into the two hues nothing else in the DG set claims.

      Yellow is deliberately not used for acids — nitric acid and potassium permanganate wearing the same colour is the confusion this is meant to prevent.

      Moving labels around
      Build sheet lays every queued label onto the page — press it again at any time to put everything back. Then click a label to select it: drag it to move, drag the blue corner to resize, and remove it with the × in its corner or the Delete key. Dashed guides show where the stickers are on the chosen sheet.
      Drop a label near a sticker and it clicks into place. Turn this off to position freely, for printing on plain paper.

      Before you print onto label sheets

      In the browser's print dialog set Scale to 100% — not “Fit to page”, which shrinks everything and pushes the labels out of alignment — and Margins to None. Turn Background graphics on so the coloured borders print.

      Do a test print on plain paper first and hold it against a label sheet before using the real thing.
